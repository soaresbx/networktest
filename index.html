Extended monitor

Intermittent problems (brief dropouts, robotic audio, Wi-Fi roaming) rarely show up in a one-minute test. This monitor checks the connection four times per second and keeps a signalling connection open, like the Aircall app does. Run it at the time problems usually happen, keep this tab visible, and keep using the network as normal.

What this test checks, and its limits
  • Required domains and WebSockets: checks that the hosts on Aircall’s allowlist (*.aircall.io, Twilio, Pusher, Intercom, AWS S3) can be reached over HTTPS, and that WebSocket connections open. A blocked host usually means a firewall, proxy, content filter or browser extension.
  • UDP: asks public STUN servers (Twilio, Google) for this network’s public address. A reply proves outbound UDP works. Without UDP, calls fall back to TCP/TLS relays, which add delay and are more prone to choppy audio.
  • TURN relay (optional): only runs if short-lived TURN credentials are added to CONFIG.turnServers in the page source.
  • Voice regions: HTTPS round-trip time to each Twilio voice edge (voice-js.<edge>.twilio.com). This is approximate and includes a little server time.
  • Latency, jitter and loss: repeated small requests to the nearest Cloudflare server, which measures your own connection. Jitter here is measured over HTTPS and runs higher than real call audio would show, so the thresholds are lenient.
  • Speed and latency under load: download/upload throughput plus how much latency rises while the line is busy (“bufferbloat”). Rising latency under load is a common cause of calls breaking up when someone else on the network is uploading or downloading.
  • Routing: flags when internet traffic leaves on a different continent from this computer’s timezone, or when the closest voice region is on another continent. Both usually point to a VPN, proxy or virtual desktop.
  • Extended monitor: samples latency 4 times per second for 2–10 minutes without filtering out spikes, counts spikes and moments with no reply, and keeps a WebSocket open (with a keep-alive similar to the Aircall app’s) to catch firewalls or VPNs that cut long-lived connections, the usual cause of the app flipping to offline. That WebSocket goes to a neutral public echo server (echo.websocket.org), because Aircall’s providers close unauthenticated connections on their own.
  • Not covered: real voice packet loss over UDP (this needs a real test call to a media server), deep packet inspection, SIP ALG on routers (affects desk phones/SIP), and Wi-Fi signal strength (browsers can’t read it; check it in the operating system). Run the test a few times, at the times calls go wrong, for a fair picture.
  • How to read the colours: blue means the check found no problem, not that the connection is guaranteed to be fine. Amber is a risk, red is a problem, grey is information or a check that couldn’t run.
  • Privacy: this page contacts Cloudflare, Twilio, Pusher, Intercom, AWS, Google STUN and (monitor only) echo.websocket.org. Results stay in your browser unless you copy or download the report.
